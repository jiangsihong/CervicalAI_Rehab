# 患者邮箱验证与登录

患者可以使用 QQ、163、Gmail、Outlook 等常见邮箱地址，不限制收件邮箱服务商。
平台只需配置一个发件账号；实际投递受发件服务商、收件方规则和网络环境影响。
邮箱验证用于确认邮箱使用权，不属于实名认证或专门的机器人识别。

## 本地启用真实邮件

1. 将 `.env.example` 复制为同目录 `.env`，仅在本机填写发件服务商提供的 SMTP 地址、端口、账号及授权码。
2. `MAIL_SECURITY=ssl` 使用隐式 TLS；`starttls` 使用 STARTTLS。连接会验证服务器证书，不支持明文发送。
3. `MAIL_FROM` 填服务商允许使用的发件地址；通常与 `MAIL_USERNAME` 相同。
4. 设置独立的随机 `SECRET_KEY`、`JWT_SECRET_KEY`。重启后端，重新构建并刷新前端。

`.env` 不会覆盖已有环境变量，且已加入版本控制忽略规则。不要在聊天或代码中填写授权码。
未配置邮件服务时会明确报错，不会假装发送成功，也不会提供可绕过验证的固定验证码。
服务商若要求 OAuth 而不允许 SMTP 授权码，请使用支持 SMTP 授权码的发件服务或单独接入该服务商的邮件 API。

## 流程与限制

- 注册：用户名 + 邮箱 + 新密码 → 获取验证码 → 验证邮箱 → 创建患者账号并登录。
- 登录：用户名或邮箱 + 密码 → 验证密码 → 向账号已有邮箱发验证码 → 提交后登录。
- 注册用户名 2–50 位，支持中文、英文字母、数字、下划线、点和短横线。姓名或称呼在个人资料填写。
- 新密码 8–128 位，至少包含英文字母和数字。旧账号登录仍接受原有短密码；修改密码时执行新规则。
- 验证码 6 位、有效期 5 分钟、单次使用、最多尝试 5 次。新码发送成功后，同邮箱同用途旧码失效。
- 同邮箱重发间隔 60 秒，每小时最多 5 次；同来源 IP 每小时最多发送 20 次。
- 密码验证同账号 15 分钟最多 15 次，同 IP 最多 60 次；获取登录验证码和提交登录均计数。
- 限制和验证码摘要存储在数据库，重启不会重置；响应、日志和数据库均不保存明文验证码。
- SMTP 失败或服务未配置时禁止跳过验证；失败发送仍计入限额，防止服务异常时重复轰炸。
- 首次登录或资料不完整时，登录成功优先进入个人中心；可选择稍后填写，不阻止自测。
- 姓名或称呼、年龄、性别用于基本资料完整度提示，手机号、病史等可选，不收集身份证号。
- 公开入口只允许患者登录，注册请求无法指定管理员或医生身份。

首次重启会通过现有 `create_all` 补齐 `email_verifications` 和 `auth_rate_limits` 两张表，不删除已有业务数据。
不要执行 `init-db`，该命令会清空业务表。

## 上线注意

本地自动化测试模拟 SMTP，不发送真实邮件。正式启用前需用自己的测试邮箱验证真实收发。
启用 HTTPS、替换开发密钥并配置受信任的代理。来源 IP 取 `request.remote_addr`；反向代理部署时须明确代理信任边界后再配置真实来源 IP，不能直接信任客户端自填请求头。
发送是同步请求：邮件服务异常时可能等待网络超时。用户量增长后可改为受控邮件队列。
